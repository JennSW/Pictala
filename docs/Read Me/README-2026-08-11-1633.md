## 3. DuckDuckGo browser testing found a real CORS bug

Jen switched to her actual default browser (DuckDuckGo, WebKit-based) to
test as a real user would, hitting `TypeError: Load failed` on sync.

- Root cause, found by reading `app/main.py`: `CORSMiddleware` only
  allowlisted `http://localhost:5173` — DuckDuckGo was likely on
  `http://127.0.0.1:5173`, a different origin as far as the browser's
  CORS enforcement is concerned, so the request never reached the
  backend at all.
- Fixed by allowlisting both origins. Confirmed via a manual `curl` with
  an explicit `Origin: http://127.0.0.1:5173` header that the response
  now carries the matching `access-control-allow-origin`.
- The DuckDuckGo retry still didn't visibly work for Jen -- see item 4,
  which explains why (a second, real UX gap, not the same bug).
